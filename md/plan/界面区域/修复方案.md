# H5 界面区域滚动修复方案

## 问题根因

当前布局结构：
```
body (overflow-y: auto, 浏览器默认)  ← 滚动容器是 body！
└── .app-shell (min-height: 100vh, flex column)  ← 可以超过视口
    ├── .main-view (flex: 1, overflow: visible)
    │   └── section (各场景页面)
    └── .nav (position: sticky, bottom: 0)  ← sticky 跟随 body 滚动
```

**核心问题**：`body` 是滚动容器，`.app-shell` 使用 `min-height: 100vh` 可以超出视口。
当 body 滚动时，**所有元素都一起移动**——顶部区域被挤出、`::before` 伪元素消失、底部 nav 跟着滚动。

## 期望布局

```
body (height: 100dvh, overflow: hidden)  ← 固定视口高度，不滚动
└── .app-shell (height: 100dvh, overflow: hidden, flex column)
    ├── [状态栏渐变] (position: fixed, top: 0, z-index: high)
    ├── .main-view (flex: 1, overflow-y: auto)  ← 只有这里滚动
    │   └── section (各场景页面)
    └── .nav (flex-shrink: 0)  ← 自然固定在底部
```

## 修改步骤

### 1. 约束 body/html 高度，禁止 body 滚动

```css
body.android-device {
  overflow: hidden;
}
body.android-device,
body.android-device html {
  height: 100dvh;
  height: 100vh;
}
```

### 2. .app-shell 固定在视口内

```css
body.android-device .app-shell {
  height: 100dvh;
  min-height: unset;
  overflow: hidden;
}
```

### 3. .main-view 变成内部滚动容器

```css
body.android-device .main-view {
  overflow-y: auto;
  overflow-x: hidden;
  -webkit-overflow-scrolling: touch;
}
/* play 页面保持自己的布局不动 */
body.android-device .main-view--play {
  overflow: hidden;
}
```

### 4. .nav 不再需要 sticky

```css
body.android-device .nav {
  position: static;
  flex-shrink: 0;
}
```

### 5. ::before 渐变改为固定定位

原来每个 section 通过 `position: absolute; top: calc(-1 * var(--android-inset-top))` 画渐变，
但 section 在 .main-view 内部滚动时伪元素会消失。改为在 .app-shell 上画一个固定的渐变条：

```css
body.android-device .app-shell::before {
  content: "";
  position: fixed;
  top: 0;
  left: 50%;
  transform: translateX(-50%);
  width: min(100%, 480px);
  height: var(--android-inset-top);
  background-image: linear-gradient(
    rgba(0, 0, 0, 0.7),
    rgba(0, 0, 0, 0.3)
  );
  z-index: 100;
  pointer-events: none;
}
```

### 6. 移除 section 上多余的 margin-top 和 min-height

```css
/* 原有：margin-top + min-height 用于撑开页面让 body 滚动 */
/* 现在 main-view 自己滚动，这些都不需要了 */
body.android-device .my-page {
  min-height: unset;
  margin-top: 0;
  padding-top: var(--android-inset-top);
}
body.android-device .create-page {
  min-height: unset;
}
/* history/hall 页面没有 min-height，保持即可 */
```

### 7. play-page 和 home-stage 保持不变

这两个页面有自己的布局体系（play-page 已使用 height: 100dvh + overflow: hidden），不需要改动。

```css
/* 保持现有规则不变 */
body.android-device .play-page .play-stage { padding-top: var(--android-inset-top); }
body.android-device .home-stage { padding-top: var(--android-inset-top); }
```

### 8. 清理不需要的旧规则

移除以下现已无效的规则：
- `body.android-device .my-page, body.android-device .main-view > section:not(.play-page):not(.home-stage)` 的 `margin-top`
- `body.android-device .my-page::before, ...::before` 伪元素规则（被 .app-shell::before 替代）
- `body.android-device .settings-header` 的 `margin-top`（settings-page 在 main-view 内部滚动，不需要）

### 9. 处理 modal 弹出层

全屏 modal 的定位需要确认不受影响：
```css
body.android-device .modal-backdrop {
  /* fixed 定位在视口上，不会受 main-view 滚动影响，无需改动 */
}
```
